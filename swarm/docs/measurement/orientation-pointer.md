# 度量记录：把生成索引当"指针指令"而不是"可选资料"

状态：一次已完成的受控 A/B 的**摘要记录**，随提交 `5f9ed9b9` 的改动一起入库（2026-11-12）。
逐 run 原始计数、transcript 与统计脚本**未随本仓库分发**。本文只固定"当时测了什么、得到什么、
什么没测"，供后续复核；它不授权启动 Agent、不改变启动契约，也不替换任何验收口径。

关联：被改动的文本 `swarm/coordinator_strict.py`（`strict_bootstrap_prompt` 里的索引行）、
`swarm/strict-bootstrap-protocol.md` §定位、`swarm-orca/AGENTS.md` §Symbol lookup；
索引本身由 `swarm/generate_orientation.py` 生成。

## 1. 要回答的问题

启动 pane 已经能拿到生成索引 `swarm/ORIENTATION.md`（路径 + 行区间，`--check` 守着），
却仍在用名字反推位置。要判断的不是"索引有没有用"，而是两件更窄的事：

1. 把索引**写成可执行动作**（"先在这里查名字，表里没有才 grep"）是否改变行为；
2. "可用但非必读"这种措辞是否足够。

## 2. 两臂

| 臂 | 启动契约里关于索引的措辞 |
| --- | --- |
| 指针臂 | 给出路径，并要求"look a name up here before searching"（即当前 `coordinator_strict.py` 那行） |
| 对照臂 | 只说"按需阅读"或不给动作指令（索引路径仍可读） |

两臂同一只读任务、同一模型，唯一差异是这条指令的措辞。任务不含代码修改、部署或远端操作。

## 3. 结果

| 指标 | 指针臂 | 对照臂 |
| --- | --- | --- |
| 符号搜索次数 | 23–29 | 33–43 |
| 模型回合 | 26.5 | 35.5 |

附带结论，同样是测量结果而非常识：

1. 收益是**更少探测**，不是"每轮探测更多"。
2. 单独的"批量/合并工具调用"规则无效：calls/turn 固定 1.72，每次消息最多 2 次调用，
   与提示文本无关。所以索引这条指令省下的是搜索次数本身。

这就是"可选资料"改成"先查这里"的依据，也是把该行留在**必读清单之外**的依据：
非必读也能生效，不需要扩大必读阅读量。

## 4. 明确未测（不得读成 0，也不得当已通过）

- **n 与分布**：被测 pane 数量、逐 pane 原始计数、方差/置信区间均未记录，只有区间与均值。
- **模型与环境**：仅记"同一模型"，模型名/版本/effort、运行时与宿主未记录。
- **任务材料**：仓库、基线 commit、提示词全文未记录；已知是只读任务。
- **计数判据**：什么算一次"符号搜索"（`grep` 名字算，读到索引给的行区间不算？）没有写成
  机器可判规则，只被人工计数。
- **原始证据**：transcript 与统计脚本在本仓库之外，未归档到 `swarm` 目录。
- **必读化 / 门禁化**：**没有对照臂**。"加进必读清单只会扩大阅读量""做成证据槽不值得"
  两条都是推断，不是测量。
- **反向风险**：表里没有条目时是否转而过度依赖索引、不再打开源码，未测。

## 5. 复现要求（若要重跑）

1. 先写可执行计数判据，再跑：例如 tool call 中 `grep`/`rg` 的参数含符号名计 1，
   `read` 落在索引给出的行区间不计，并把判据留在本目录。
2. 两臂只差这一行文本；任务、模型、基线 commit 相同并留存。
3. 记录 n、模型与版本、逐 pane 原始计数与回合数，落盘到本目录，不要只写进提交信息。
4. 报告分布而不只是均值；单次对比不得外推成"下一个任务会省 N%"。
