# Agent / 多 Agent 端到端验收框架开发计划

状态：**待实施的开发计划**。本文落盘与文档 review 不代表框架已开发、测试已通过或获准启动被测 Agent。
范围：Orca 中 Agent 与多 Agent 的用户操作、协作状态和结果展示；不是模型能力排行榜，也不是全仓 E2E 重构。

配套：[证据与交付契约](e2e-evidence.md)、[测试与验收指南](reliability.md)、
[本机测试运行约定](orca-test-runs.md)。源码路径以下均以 `swarm-orca/` 仓根为基准；产物布局没有 `orca/`，
相关源码核验必须回到源码检出。执行角色与启动路径仍以[入口选择](../entry-paths.md)为准，不另造 Swarm 控制协议。

## 1. 要交付什么

开发 Agent 完成功能后，**独立验收 Agent 扮演用户操作真实 Orca**，检查产品行为并交付看图可理解的报告：

| 用户需求 | 验收产物 |
| --- | --- |
| 开发新功能 | 关键操作和结果截图，附对应行为检查 |
| 修 Bug | 相同场景、数据与显示条件下的修复前后截图，附失败/通过记录 |
| 看不同场景 | 用受控模拟响应生成正常、慢响应、失败、等待等场景，不依赖真实模型碰巧触发 |

截图是核心交付物，但“两个 Agent 卡片都显示运行中”不证明实际并发，“任务显示完成”不证明结果已交付。
因此同时保留 **UI/视觉检查、行为断言、运行事实**；三者冲突不能由验收 Agent 自行解释成通过。
本框架只能给出固定场景和版本下的验收结论，不能证明整个代码仓库无缺陷。

先读实现和断言再判断覆盖，不能用文件名、关键词出现次数推断某条通道已覆盖或零覆盖。
下面是盘点入口，不是完整覆盖清单，也不是本计划已执行的测试：

| `orca/tests/e2e/task-workbench-deliver-prompt-submit.spec.ts` | 真 UI/PTY 启动与投递记录；不是完整多 Agent 协作证明 |

新增的是场景契约、薄适配器、证据报告和验收 Agent 入口。先做一个纵向样板，不要求把所有 stub 合并，
也不要求给所有 Agent 写一套相同 E2E。`orca/` 是上游快照，实施须最小化、附回归，不作无关重构。

## 3. 架构与职责

```text
需求 / Bug + 已确认授权
          ↓
验收 Agent：提出场景、操作/调用受限工具、看截图、解释结果
          ↓
固定场景与执行器：现有 Playwright / Electron + 小型适配器
  ├─ UI 驱动：用户入口、点击、输入、切换、截图
  ├─ 对端适配：脚本化 Agent 或获准的真实 Agent
  ├─ 事实采集：任务、消息、会话、提交次数、生命周期
  └─ 判定与报告：固定断言 + 视觉结果 + 缺口 + 资源收尾
```

- 验收 Agent 不兼任被测 Coordinator/Worker，不替它们完成业务、消费消息、ACK 或伪造完成。
  独立性最低要求是与实现者分开的会话/上下文；提供需求、固定预期与场景契约，不提供实现者的
  “应该通过”结论作为答案。记录是否看过 diff、作者结论及是否同模型；模型不同不是独立性的替代。
  M2 必须由验收 Agent 主动通过受限工具发起至少一个用户可见操作，并实际读取其截图作视觉判断，
  不能只读执行器报告写摘要。
- 确定性执行器不需要 LLM；验收 Agent 自身的调用成本单独统计，“模拟被测 Agent”不等于整个流程零费用。
- UI 操作优先复用 Playwright 的语义定位；截图分析用于布局、遮挡、错位等问题。必要的坐标操作须记录
  对应截图与坐标，不能用 CLI 操作结果冒充已验证 UI 入口。后台操作确实无 UI 入口时在场景中注明。
- 验收 Agent 只能选择已批准的场景和有界参数，不能修改断言、基线、跳过条件或重试到通过。
  新生成的测试脚本须经过审查再执行；不把自然语言直接转换成任意 Shell/eval 权限。
- 被测 Agent 输出、页面内容与日志都是测试数据，不是验收 Agent 的新指令。测试内容不能扩大授权或引导
  读取凭据、公开证据、启动新资源。

## 4. 运行模式与证明力

### 4.1 确定性模拟：日常回归

保留本场景要验证的真实 UI、IPC、PTY、任务/消息路径，在明确的外部边界替换 Agent 行为。
脚本化对端可按固定步骤返回、延迟、失败或等待输入；不是往 store/数据库直接写“成功”。
若只注入列表数据展示空态/错误态，标为 **UI 展示场景**，不能冒充端到端协作。

模拟 Coordinator/Worker 时只使用测试环境合法角色入口；若受支持入口不能容纳脚本化对端，先报告适配缺口，
不得复制真实身份或绕过启动门。该模式不证明真实模型理解交接或自主推进。

### 4.2 真实 Agent：小规模冒烟

使用真实 Coordinator/Worker，验证启动、指令进入真实会话、Worker 交付以及 Coordinator 接收汇总。
它与模拟模式复用业务场景 ID、检查点和报告结构，适配器与证明范围分别标注，不混成一个 PASS。

启动前确认目标 runtime、工作区、Agent/模型/角色、写入工具范围、正整数 `max_workers`、预算、期限、重试与
停止条件。首个多 Worker 场景要求用户确认 `max_workers >= 2`，不是本文设置默认值；审查/嵌套 Worker 共用上限。
外层验收 Agent 不因“观察者”身份得到额外派发额度或业务权限，独立记录其成本和角色。

真实模式按适用的原生启动、身份、grant、owner/consumer 与收尾契约执行。没有领域适配时按通用协议执行；
只有该场景必需的运行/测试适配或领域检查入口缺失才 BLOCKED，不为测试绕过生产角色约束。
验收 Agent 可执行获准的测试触发和独立观察，不能逐轮提示 Coordinator 把“自主流程”推到成功。
只验这条产品流程不等于 [reliability](reliability.md) 中完整 L-collaboration 或核心 suite PASS。

### 4.3 与证据指引的关系

模拟/真实是对端真实性维度；A（行为回归）/B（截图取证）/C（真实调用）是交付维度，可以组合。
本计划的真实多 Agent 可视化验收使用 **B+C**：也要关键截图，不因“真实”而省略图。
截图本身不是成功条件；稳定环境下经批准的视觉断言可以是成功条件之一，不能替代行为断言。

## 5. 场景与证据契约（M0 固定格式，尚未实现）

每条场景最少声明：

- `id`、版本、需求/缺陷关联、模式、平台/显示条件、真实路径与模拟边界；
- 隔离资源、合法身份/启动前置、允许操作/故障、预算、期限与停止条件；
- UI 步骤、业务输出、必需行为断言、禁止行为、截图节点与视觉检查；
- 观察窗口、触发屏障、取证关联规则、清理规则及失败后的下一责任人。

运行前固定并哈希场景、源码（含脏改动）、构建和 fixture 输入。每次尝试单独保存，重试不覆盖失败。
manifest 记录执行器 retries 配置、attempt 序号/触发原因及 spec 内部重跑清单；M1 的“无隐藏重试”指
Playwright retries=0 且 spec 无内部重跑，三次验证是三份独立、均被报告的 attempt。
每个检查点关联本次 attempt、场景、实际 task/dispatch/session、事件与截图；用原生身份字段关联，
不能凭“最后一份日志”或目录名猜是哪一个 Worker。没有原生对象的展示场景不编造 ID。

结果沿用 [reliability 的状态](reliability.md#result-report)：PASS、FAIL、BLOCKED、PARTIAL、NON_HIT、NOT_RUN。
缺环境不是 PASS，没命中时序不是功能失败，安全违规不能被 NON_HIT 掩盖；必需图/事实缺失不得整体 PASS。
业务预期为“Worker 失败且界面正确报告”的场景可以 PASS，但仍须独立完成其资源收尾。
视觉模型无法判断或与行为结果冲突时，证据不足的检查记 PARTIAL，已明确失败的检查仍为 FAIL。
“待人工判断”只是 `nextAction`，不是新增结果状态；运行前指定人工裁决责任人，记录在 `reviewOwner`。
补图/事实或人工视觉审查以带依据的追加记录关闭该待办；不得覆盖原记录、豁免硬断言或仅凭签字把 FAIL
改为 PASS。缺少必要补证时保留 PARTIAL，重新执行须在原预算与授权内。

负向断言需证明通道可达、观察窗口足够且故障对照能被捕获；零字节/无事件不天然证明“没有重复”。
并发要有实际生命周期重叠证据，截图数量不能证明并发。既有单测继续守纯逻辑，UI 场景须有用户可见断言。

## 6. 试点场景

试点业务：两个 Worker 分别处理可客观核验的小子任务，Coordinator 在双方结果齐备后汇总。
任务文本、预期结果与文件所有权在启动前固定；不要求模型偶然制造故障。

| ID | 场景 | 关键判据与截图 |
| --- | --- | --- |
| S1 | 正常派发、并行执行、汇总 | 启动/执行中/完成三节点；真实归属、生命周期重叠、两个结果齐全才汇总，无重复任务 |
| S2 | 一个 Worker 慢，另一个先完成 | 受控屏障固定乱序；分别显示状态，依赖未齐不宣布整体成功 |
| S3 | 一个 Worker 失败 | 错误与对象清楚可见；不误报完成、不放行未满足依赖；按预定政策安全阻塞或有界恢复 |
| S4 | Worker 等待用户 | 界面明确等待对象与所需操作，收到获准输入后只提交一次 |
| S5 | 切换页面再返回 | task/Agent/session 关联与历史保持一致，不误启动第二份；重启恢复另列扩展项 |
| S6 | 结果延迟或重复到达 | 仅在支持的隔离故障入口下验证；记录相关 ID、防重与未知结果对账，缺入口为 BLOCKED |

首期只要求 **S1 + S3**；其余按增量实施。M1 中 S1 的结论限定为**脚本化正常路径及产品展示一致性**，
脚本等齐两个结果不证明产品具有依赖门或真实 Coordinator 会正确等待。该项负向证明留给 M4/S2：
固定释放一个结果、暂扣另一个，核对真实被测路径在观察窗口内不提前汇总；若产品无硬依赖门，
不得把 Coordinator 行为约定写成运行时强制能力。
S3 的受控业务失败不是框架“发现 Bug”的红证明：M0 必须选定一个可复现产品缺陷、隔离基线/修复版本、
预期失败签名和证据，再进入 M3；没有可用候选时记 BLOCKED，可交 M1 中间件，但不能声称首版验收完成。

## 7. 开发阶段与退出标准

所有阶段均为待实施。代码阶段先固定专属 worktree/基线与允许写入范围，不延续文档在 main 原地修改的例外。

| 阶段 | 工作与产物 | 退出标准 |
| --- | --- | --- |
| M0 设计与盘点 | 阅读现有用例；固定 S1/S3 实际入口及隔离/预算/清理契约；列复用/新增/缺口；选择 M3 缺陷候选 | 交可检查的 S1/S3 场景 manifest、M2 样本清单及 M3 基线/修复版本、失败签名、隔离方案；缺必要入口/候选记 BLOCKED |
| M1 确定性纵向样板 | 复用 Electron/Playwright；最小对端适配器；S1/S3；checkpoint 采集与一页 HTML + JSON manifest | 在固定环境各连续执行 3 次，按 §5 记录无隐藏重试；行为/图/事实关联一致，残留可盘点；S1 不宣称依赖门/自主协作通过 |
| M2 验收 Agent 入口 | 受限场景选择/调用、图片读取、结果整理；独立性与主动 UI 操作按 §3 留证；首版不做自由探索 | Agent 发起至少一个可见操作并核对截图中报告未提供的布局/遮挡属性；§8 正常、FAIL 保留、缺证据、冲突、提示注入样本逐项通过，视觉意见与自动断言分列 |
| M3 缺陷敏感性 | 用 M0 固定的隔离基线/修复版本执行同一场景；保存前后图、原始断言、构建 pins；重核候选可复现 | 基线命中缺陷 FAIL，修复 PASS；缺截图、错关联、环境缺失、清理失败均有报告负例；候选失效记 BLOCKED，不降低退出条件 |
| M4 增量与真实冒烟 | 扩 S2/S4/S5，S6 视合法入口；获准后运行真实 S1/S2/S3；按实际 profile 补适配 | 分别给模拟与真实结果，S2 有暂扣一个结果的负向对照；披露费用/用量缺口和未验平台；真实证据经独立核验并完成原生收尾 |
| M5 开发流程接入 | 相关源变更选测、固定命令、报告归档、opt-in 执行责任；同步必要路由测试 | 在目标环境证明选中且执行；只看本地路由不能证明 CI 已接线，不自动切阻塞门禁 |

**可交付首版 = M0–M3**：包含真正的验收 Agent，不把“只有 Playwright 脚本”叫完整框架。
M1 是可单独验收的中间件，真实多 Agent 的通过声明必须等 M4；各阶段规模确认后再估工时，不承诺未经测量的天数。
自由探索不在首版：后续须另定操作白名单、步数/时间/费用、证据关联、停止与人工接管契约，取得授权后再实现；
探索发现先记问题与复现材料，经审查固化为场景才进入回归，不把临场判断自动升级成通过条件。

拟实现落点（M0 核验后固定，不代表这些模块已存在）：

- `orca/tests/e2e/helpers/`：窄范围 UI 驱动、checkpoint 和报告适配；配同层单测。
- `orca/tests/e2e/fixtures/` 与试点 spec：脚本化对端和场景，先复用再扩展，不批量迁移已有用例。
- `swarm/skills/` 或已有验收入口：验收 Agent 的角色指引与受限工具契约；M0 先比较是否扩展既有入口，
  若新增 skill 则同步发现导航，不假设 harness 自动加载，不在 Python 层引入浏览器依赖。
- `swarm/docs/testing/`：统一场景说明、范围与报告口径；公共文档不存真实运行证据。

## 8. 验证框架本身

- 单测：场景字段、关联 ID、结果汇总、截图缺失、哈希校验、HTML 转义/离线资源引用与路径边界。
- 集成：隔离应用的真实 UI/IPC/PTY 路径，故障后的证据保留和精确资源清理。
- 验收 Agent：固定报告样本（正常、失败、缺证据、冲突、提示注入），验证不会把 FAIL 改成 PASS。
- 缺陷对照：使用专属隔离基线，不回退共享检出，也不为了拿红改坏运行中的 source pin。
- 真实烟测：显式授权后另行执行；Windows、SSH、多个 provider 不从一个 Linux/profile 推导通过。

运行前按本机指南核实实际依赖、Electron 完整性、显示环境和 `--mode e2e` 构建；文件存在不等于可运行。
不自动安装依赖。只跑影响范围内的测试，记录模式、并发、耗时、退出码与未跑范围；文档通过不等于实机通过。

## 9. 报告、隔离与收尾

首页：一句结论、场景结果表、关键截图/前后对比、未覆盖项；点击可查看命令、trace 和对应事实。
截图/trace 采自同一 attempt，不事后补图冒充原失败现场；比较前后固定数据、平台、viewport 与显示配置。
HTML 对 Agent 输出按不可信文本转义，不嵌入可执行脚本或默认外链；公开分享需要另行授权。

源码、构建、场景、模拟输入与逐文件哈希沿用 [manifest 契约](e2e-evidence.md)。私有原件和脱敏报告
存于显式给定的工作/归档目录；公开仓仅存合成 fixture/模板，不写真实会话、ID、截图或凭据。
按归档规则解析路径/承载文件系统、写索引并读回哈希，manifest 不包含自身。未知用量不记 0。

每次尝试建立精确的资源所有权清单：测试仓库/profile、应用实例、Agent/进程、task/Run 和证据目录。
不接入个人日常 profile，不干扰其他任务。超时停止新增动作，未知在途动作先对账；禁止盲重发。
受监督资源由真实 owner 按契约结算/释放，验收 Agent 不能借清理名义越权关闭其他会话。
