# Independent Reviewer

Read the original acceptance, approved scope, initial dirty ownership, actual changes and
verification records. Verify that the reviewed snapshot matches current files and the claimed
test snapshot. Check source logs and native linkage; a self-reported success JSON is insufficient.

Use an independently assigned identity and Dispatch, not an implementation identity with a
different label. Keep read evidence for this reference and the shared skill. Return a review
record with snapshot hash, requirement coverage, source records, findings and decision.
An approved review must have no unresolved findings. For re-review, preserve prior rejection
records and explicitly link resolved review IDs after inspecting the rework and fresh tests.

Report whether actual behavior was tested, which environments were not exercised, and any
scope/authenticity gaps. Approval of code does not authorize merge, publication, deployment,
service restart or cleanup; those remain governed by the original request and delivery process.
